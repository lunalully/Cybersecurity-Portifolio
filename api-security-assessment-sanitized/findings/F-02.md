# F-02 — Duplicação Massiva de CNPJ — Constraint Unique Ausente & Sem Lock de Race

- **Severidade:** HIGH
- **CVSS v3.1:** 8.1 (AV:N/AC:L/PR:L/UI:N/S:U/C:N/I:H/A:H)
- **CWE:** CWE-362 (Race Condition) / CWE-697 (Comparação Incorreta)
- **OWASP 2021:** A04 — Insecure Design
- **MITRE ATT&CK:** T1498 — Network Denial of Service · T1078 — Valid Accounts

---

## Descrição

O endpoint `POST /store` não aplica unicidade do campo `cnpj`. Uma única conta conseguiu
registrar **32 lojas** compartilhando o mesmo CNPJ em ~60 segundos — 11 duplicatas
sequenciais, 10 em burst paralelo e 20 em um segundo burst paralelo — todas retornando
`200 OK` com IDs de loja distintos. Nunca foi retornado `409 Conflict`.

Como o CNPJ é um identificador fiscal, o schema do banco carece de constraint `UNIQUE(cnpj)`
e o handler não faz pré-checagem. Requisições paralelas confirmam a ausência de qualquer
lock: todas as criações concorrentes tiveram sucesso.

## Impacto

- Confusão de identidade fiscal: CNPJs duplicados impossibilitam atribuir lojas a pessoas
  jurídicas reais.
- Habilita criação em massa de vitrines que, combinada com F-01, transforma a plataforma em
  vetor de abuso (lojistas falsos, abuso de configuração de pagamento, spam de reputação).
- O burst paralelo (30 lojas em segundos) também atua como caminho de escrita sem
  throttling (ver F-06).

## Evidência (sanitizada)

```bash
# 10 requisições paralelas, mesmo CNPJ, slugs diferentes
for i in $(seq 1 10); do
  curl -sk -X POST https://api.example.com/store \
    -H "Authorization: Bearer <customer_jwt>" \
    -H "Content-Type: application/json" \
    -d '{"name":"Dup Store","slug":"dup-'$i'","cnpj":"19.131.243/0001-97"}' &
done; wait
```

Resultado — `10 × 200 OK` com IDs de loja **distintos**:

```
a91e34d…-…-…  200
40fb30e…-…-…  200
c29793…-…-…   200
...
```

Verificação `grep cnpj` nas lojas criadas → 11+ registros com CNPJ idêntico.

## Remediação

1. Adicionar `UNIQUE(cnpj)` na camada do banco e retornar `409 cnpj already exists`.
2. Tratar o race explicitamente: constraint unique + mapeamento de retry, ou semântica
   `INSERT ... ON CONFLICT`.
3. Adicionar um teste de regressão rodando `N` criações paralelas com o mesmo CNPJ e
   afirmando exatamente um `200`.
