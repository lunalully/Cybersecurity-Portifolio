# F-06 — Rate Limit Ausente na Criação de Loja

- **Severidade:** MEDIUM
- **CVSS v3.1:** 5.3 (AV:N/AC:L/PR:L/UI:N/S:U/C:N/I:N/A:L)
- **CWE:** CWE-770 (Alocação de Recursos Sem Limites ou Throttling)
- **OWASP 2021:** A07 — Identification and Authentication Failures
- **MITRE ATT&CK:** T1110 — Brute Force (abuso de conta / abuso de recurso)

---

## Descrição

`POST /store` não tem rate limit. Uma única conta `customer` criou **32 lojas em menos de 60
segundos** com zero respostas `429`. Em contraste, os endpoints de autenticação são
corretamente limitados a 10 requisições/minuto. Isso significa que o caminho de criação de
loja — um caminho de escrita que executa lógica de CNPJ/domínio e inserts no banco — não tem
throttling e pode ser acionado em velocidade total por qualquer usuário autenticado.

## Impacto

- Consumo massivo de recursos e amplificação de escrita no banco.
- Combinado com F-01 e F-02, um atacante pode instanciar centenas de vitrines em minutos para
  apoiar fraude, spam ou abuso de reputação.
- Contribui para o "caminho de escrita sem throttling" que enfraquece a plataforma durante
  bursts.

## Evidência (sanitizada)

```bash
# 32 criações sequenciais+paralelas em < 60s
# cada resposta: HTTP 200 OK — zero 429
seq 1 32 | xargs -P 8 -I{} curl -sk -X POST https://api.example.com/store \
  -H "Authorization: Bearer <customer_jwt>" \
  -H "Content-Type: application/json" \
  -d '{"name":"Mass Store {}","slug":"mass-{}","cnpj":"19.131.243/0001-97"}' \
  -w '%{http_code}\n' -o /dev/null
```

Saída: `200 200 200 200 …` (32 vezes)

## Remediação

1. Aplicar rate limit (ex. 10/min por usuário/IP) ao `POST /store`, igualando os endpoints de
   auth, com o mesmo limiter backed by Redis.
2. Adicionar a rota de criação de loja à matriz automatizada de testes de rate limit.
