# F-08 — Validação de Assinatura de Webhook é Fail-Open Quando Secret Ausente

- **Severidade:** LOW
- **CVSS v3.1:** 5.3 (AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:L/A:N)
- **CWE:** CWE-1188 (Inicialização Padrão Insegura de Recurso)
- **OWASP 2021:** A08 — Software and Data Integrity Failures
- **MITRE ATT&CK:** T1195 — Supply Chain Compromise (injeção de evento)

---

## Descrição

O handler do webhook de billing pula a validação de assinatura quando a variável de ambiente
do secret do webhook da plataforma está **vazia**. Conforme o inventário do código-fonte, "se
a env var estiver vazia, o handler não valida a assinatura". Em qualquer ambiente onde a
variável não esteja configurada (ex. um clone/staging esquecido ou um deploy novo), o webhook
de billing se torna completamente não autenticado: um atacante poderia forjar eventos de
pagamento e mutar o estado de billing/pedidos.

## Impacto

- Em um ambiente mal configurado, eventos forjados de pagamento/settlement poderiam ser
  injetados sem autenticação.
- A postura de segurança depende de uma variável de runtime estar corretamente definida, em
  vez de um comportamento fail-closed.

## Evidência (sanitizada)

Observação a nível de código (paráfrase do inventário):

```go
// if os.Getenv("ASAAS_PLATFORM_WEBHOOK_SECRET") == "" {
//     // handler prossegue SEM validação de assinatura
// }
```

## Remediação

1. Falhar **fechado**: se o secret não estiver definido, retornar `503 Service Unavailable` e
   logar um alerta — nunca processar a requisição.
2. Adicionar um check/gate de health no deploy que se recuse a iniciar (ou a registrar a rota
   de webhook) quando o secret estiver vazio.
3. Verificar que produção tem um secret não vazio e adicionar teste de CI com a env ausente.
