# F-05 — 500 Não Tratado em `menu/category` e Lookup de User Admin

- **Severidade:** MEDIUM
- **CVSS v3.1:** 5.3 (AV:N/AC:L/PR:L/UI:N/S:U/C:N/I:N/A:L)
- **CWE:** CWE-248 (Exceção Não Capturada) / CWE-390 (Detecção de Condição de Erro Sem Ação)
- **OWASP 2021:** A05 — Security Misconfiguration
- **MITRE ATT&CK:** T1499 — Endpoint Denial of Service

---

## Descrição

Dois endpoints retornam `500 internal error` não tratado para entradas que deveriam ser
tratadas como erros de validação:

| Endpoint | Entrada | Resultado |
|----------|---------|-----------|
| `POST /menu/{id}/category` | payload vazio, autenticado | `500 internal error` |
| `GET /admin/user/{invalid-id}` | valor não-UUID | `500 internal error` |

O endpoint `POST /store` com payload vazio corretamente retorna `400`, o que mostra que a
inconsistência é localizada em handlers específicos que não têm validação de entrada e
entram em panic (ou sobem um erro inesperado) em vez de retornar `400 invalid_argument`.

## Impacto

- Abuso do caminho de erro para poluição de logs e exceções ruidosas.
- Mascara a causa raiz real dos clientes; dificulta o triage para o time da plataforma.
- O `500` em um ID admin inválido também indica falta de checks defensivos em um caminho
  privilegiado — indicador de qualidade de que handlers privilegiados devem ser revisados.

## Evidência (sanitizada)

```bash
curl -sk -X POST https://api.example.com/menu/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx/category \
  -H "Authorization: Bearer <store_jwt>" -H "Content-Type: application/json" -d '{}'
```

```http
HTTP/1.1 500 Internal Server Error
{"error":"internal error"}
```

```bash
curl -sk https://api.example.com/admin/user/not-a-uuid \
  -H "Authorization: Bearer <admin_jwt>"
```

```http
HTTP/1.1 500 Internal Server Error
{"error":"internal error"}
```

## Remediação

1. Validar entrada antes de qualquer operação de domínio; retornar `400 invalid_argument` com
   detalhes.
2. Usar middleware de recovery que mapeie panics para `500` apenas como último recurso,
   logando o stack trace no servidor.
3. Adicionar teste de regressão: payloads vazios/inválidos nunca devem gerar `5xx`.
