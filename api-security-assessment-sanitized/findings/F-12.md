# F-12 — Inconsistência de Nomenclatura de Role (`store` vs `store_owner`)

- **Severidade:** LOW
- **CVSS v3.1:** — (informacional / higiene)
- **CWE:** CWE-710 (Adesão Impropria a Padrões de Codificação)
- **OWASP 2021:** A07 — Identification and Authentication Failures
- **MITRE ATT&CK:** —

---

## Descrição

A resposta de login retorna `role: store` enquanto o payload do JWT codifica
`role: store_owner`. Customers fazem login como `customer`, admins como `admin`, mas a role
de lojista está dividida entre dois nomes. Nenhum bypass de autorização foi observado — o
middleware RBAC e os handlers usam o `store_owner` do JWT de forma consistente — mas a
inconsistência cria confusão e um risco de manutenção: qualquer caminho de código que
compare com `store` (da resposta de login) falhará silenciosamente contra um JWT que diz
`store_owner`.

## Evidência (sanitizada)

```json
// resposta de login
{ "role": "store" }

// payload do JWT decodificado
{ "role": "store_owner", "iss": "saas-core", "exp": 1756…, "jti": "…" }
```

## Remediação

Padronizar `store_owner` em todo lugar (resposta de login, claims do JWT, checks de RBAC,
documentação). Adicionar um teste de contrato afirmando a igualdade do nome da role entre
login, token e middleware.
