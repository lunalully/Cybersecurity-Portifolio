# F-04 — 500 Descontrolado em Null-Byte / Payload Grande

- **Severidade:** MEDIUM
- **CVSS v3.1:** 6.5 (AV:N/AC:L/PR:L/UI:N/S:U/C:N/I:N/A:H)
- **CWE:** CWE-400 (Consumo Descontrolado de Recursos) / CWE-170 (Terminação Nula Impropria)
- **OWASP 2021:** A03 — Injection
- **MITRE ATT&CK:** T1499 — Endpoint Denial of Service

---

## Descrição

`PATCH /user/profile` retorna `500 internal error` em vez de um `400`/`413` adequado para
entradas malformadas ou grandes:

| Payload | Resposta | Notas |
|---------|----------|-------|
| `{"name":"teste\u0000"}` | `500 internal error` | null byte não rejeitado |
| `{"name":"A"×5000}` | `500 internal error` | sem `413 Payload Too Large` |
| `{"name":"A"×100000}` | `500 internal error` | reproduzível 3/3 |
| `{"name":12345}` / `[]` / `{}` | `400 invalid request body` | tipagem estrita OK |

O null byte provavelmente sobrevive até a camada de storage (panic no driver do DB ou uma
conversão de string-bytes), enquanto payloads grandes são aceitos pela camada HTTP sem guarda
de tamanho de corpo. Ambos produzem um caminho de erro não tratado que aparece como `500`
genérico.

## Impacto

- Uma única requisição gera caminho de exceção; requisições repetidas (30 payloads paralelos
  de `5k`) produziram `500`s, mas o serviço permaneceu saudável (`/health` continuou `200`),
  então não é DoS completo — porém polui logs, pode queimar CPU em caminhos de erro e mascara
  falhas reais de validação de entrada.
- A ausência de `413` significa que não há limite superior de tamanho de corpo antes do
  handler.

## Evidência (sanitizada)

```bash
curl -sk -X PATCH https://api.example.com/user/profile \
  -H "Authorization: Bearer <customer_jwt>" \
  -H "Content-Type: application/json" \
  -d '{"name":"B000000000000000000000…5000"}'
```

```http
HTTP/1.1 500 Internal Server Error
{"error":"internal error"}
```

## Remediação

1. Rejeitar caracteres de controle (`\x00`) na validação antes da persistência → `400`.
2. Aplicar limite de tamanho de corpo no servidor/Gateway (`max_body_bytes`, ex. 1 MB) e um
   limite de comprimento de nome (`len(name) < 100`) → `413` / `400`.
3. Substituir a resposta de erro genérica por erros estruturados (`error code + details`) e
   logar a exceção com o `x-request-id` para correlação.
