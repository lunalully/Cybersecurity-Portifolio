# F-15 — `POST /store` como Customer Retorna 400 em vez de 403

- **Severidade:** INFO
- **CWE:** CWE-205 (Discrepância Comportamental Observável)
- **OWASP 2021:** A01 — Broken Access Control

## Descrição
Um `customer` autenticado chamando `POST /store` recebe `400 invalid_argument` (validação de
CNPJ) em vez de `403 insufficient permissions`. Se customers não devem criar lojas, o check
de autorização deveria acontecer antes da validação; do contrário, o endpoint vaza as regras
de formato do CNPJ e representa mal o modelo de autorização.

## Evidência (sanitizada)
```
POST /store (customer token) {"cnpj":"..."} → 400 invalid_argument  (não 403)
```

## Remediação
Executar o check de role antes da validação de negócio; retornar `403` para roles não
autorizadas.
